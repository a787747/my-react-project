## Step 4 — Firewall (`DOCKER-USER`, plus `INPUT` for Swarm)

**Change:** `/usr/local/sbin/epe-firewall.sh` + systemd `epe-firewall.service` (`After=docker.service`, enabled) + docker drop-in `ExecStartPost=` so Docker’s iptables rewrite does not drop the jump.

`iptables-persistent` is **not** installed. Saving Docker’s live `DOCKER` chain with netfilter-persistent races Docker on boot. The systemd unit is the equivalent that actually survives `restart docker` and reboot (proven in Steps 5 and 8).

Allowlist IPv4: `212.36.169.90` (this workstation, `curl -4 ifconfig.me` this session). IPv6: those ports DROP with no allow (host has no public IPv6 on `eth0`).

Published ports are matched **after DNAT** via `--ctorigdstport` (host `5431` becomes container `5432`). Interface `eth0` only.

Swarm `2377`/`7946`/`4789` are **host** listeners (`dockerd`), not Docker-published ports. `DOCKER-USER` never sees them. The same ALLOW/DROP intent is applied on `INPUT`. Duplicate `DOCKER-USER` rules for those ports are present and stay at 0 packets — expected.

`5678` and `22` are not in the DROP list.

**Rollback:** `systemctl disable --now epe-firewall.service`; `rm /etc/systemd/system/docker.service.d/epe-firewall.conf`; `iptables -D DOCKER-USER -j EPE-DOCKER-USER`; `iptables -D INPUT -j EPE-INPUT`; `iptables -F EPE-DOCKER-USER; iptables -X EPE-DOCKER-USER` (and the same for `EPE-INPUT` / ip6tables); `systemctl daemon-reload`.
